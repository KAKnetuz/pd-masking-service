# Правила работы в проекте pd-masking-service

## Что это за проект
Сервис маскирования и демаскирования персональных данных для хакатона Альфа-Банка.
Python 3.12 + FastAPI. Развёртывание: docker compose (api + redis) на ВМ.

## Контракт API — менять запрещено
POST /process, тело {"payload": "<строка>", "payload_id": "<строка>"}, ответ {"result": "<строка>"}.
Первый запрос с новым payload_id — маскирование, второй с тем же payload_id и нашей маской — демаскирование.
Повтор запроса с исходным текстом должен возвращать ту же маску (идемпотентность).

## Жёсткие правила
1. Никогда не логировать текст payload, result, найденные значения ПД, ключи и секреты. Только метаданные (типы ПД, длины, время).
2. Не менять контракт /process и формат ответа.
3. Вид масок настраивается в config/systems.yaml. Если задачу можно решить конфигом — меняй конфиг, а не код.
4. Новый тип ПД добавляется так: элемент в PDType (app/core/entities.py) → детектор в app/core/detectors/ → регистрация в registry.py.
5. Не добавлять новые зависимости без явной просьбы.
6. Не трогать .env, секреты, Dockerfile и docker-compose.yml без явной просьбы.
7. Делать только то, что просят в задаче. Без рефакторинга «заодно».
8. Оболочка — Windows PowerShell: не используй &&, выполняй команды по одной или через ;.
9. Файлы с кириллицей не записывать через PowerShell (Set-Content, Out-File, echo, >): PowerShell 5 портит кодировку. Только инструмент записи файлов или Python с encoding="utf-8".

## После каждого изменения
- Запусти: ruff check . и pytest -q
- Если тест падает — исправь или сообщи, не отключай тест.
- На каждое новое поведение добавь тест в tests/.
- Если изменён файл не на Python — проверь его своим инструментом: k6-скрипты командой
  & "$env:USERPROFILE\tools\k6\k6-v2.2.0-windows-amd64\k6.exe" inspect <файл>,
  YAML — загрузкой через python -c "import yaml,sys; yaml.safe_load(open(sys.argv[1], encoding='utf-8'))" <файл>.
  Никогда не оставляй в файлах куски своего ответа или markdown-разметку.

## Отчёт в конце каждой задачи (по-русски)
1. Какие файлы изменены и зачем.
2. Как теперь проходит запрос через изменённый код.
3. Результат ruff и pytest.
4. Что может сломаться и как откатить.
